    How to use the JWT Debugger
    
    
  
    
  
    
    
    What is a JWT?
    
    
    A JSON Web Token is three base64url parts joined by dots: a header (which algorithm signed it),
      a payload (the claims, such as who the user is and when the token expires) and a
      signature. Anyone can read the header and payload; the signature only proves the token
      was not changed by someone without the key. Do not put secrets in a payload.
    

    
    Decode & verify
    
    
      
      
    • Paste a token on the left. A leading Bearer  and stray spaces or line breaks are ignored.
      • 
      
    • The right side shows the decoded header and payload, what each claim means, and whether the token has expired or is not valid yet. Hover a field name for a description.
      • 
      
    • To check the signature, enter the key under Verify signature:
        
        
          
      • HS256/384/512: the shared secret. Tick Secret is base64-encoded if your secret is stored that way.
        • 
          
      • RS, PS, ES and EdDSA: the public key as PEM (BEGIN PUBLIC KEY or BEGIN RSA PUBLIC KEY), an X.509 certificate (BEGIN CERTIFICATE), a JWK, or a whole JWKS. With a JWKS the key whose kid matches the token is used. A private key works too; its public half is used.
        • 
        
      
      
      • 
      
    • Edit in encoder copies the header and payload to the encoder so you can change a claim and sign it again.
      • 
    
    

    
    Encode & sign
    
    
      
      
    • Pick an algorithm, edit the header and payload JSON, and give a signing key. The token updates as you type.
      • 
      
    • Generate makes a random secret, or a new key pair for RS, PS, ES and EdDSA. The private key goes in the key box; the matching public key appears on the right as PEM, JWK or JWKS.
      • 
      
    • Accepted private keys: PEM (BEGIN PRIVATE KEY, BEGIN RSA PRIVATE KEY, BEGIN EC PRIVATE KEY) or a JWK that includes "d".
      • 
      
    • The iat = now and exp buttons set the time claims for you. JWT times are seconds since 1 January 1970 (UTC).
      • 
      
    • Open in decoder loads the token with the matching key, so you can see it verify.
      • 
    
    

    
    Supported algorithms
    
    
    HS256, HS384, HS512, RS256, RS384, RS512, PS256, PS384, PS512, ES256, ES384, ES512 and EdDSA / Ed25519
      (Ed25519 needs a recent browser). Tokens with alg: none are decoded and flagged as unsigned.
    

    
    Privacy
    
    
    Everything happens inside this page using the browser's built-in Web Crypto. Tokens and keys are never uploaded,
      and they are not saved: reloading the page clears them. Only your theme choice is remembered. Key URLs in a token
      header (jku, x5u) are shown but never fetched.
    

    
    Not supported
    
    
      
      
    • Encrypted tokens (JWE, five parts).
      • 
      
    • ES256K and other algorithms the browser's Web Crypto does not offer.
      • 
      
    • Password-protected private keys. Remove the password first, for example openssl pkey -in key.pem -out plain.pem.
